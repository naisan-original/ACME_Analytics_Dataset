# ACME Analytics Synthetic Dataset

A seeded, config-driven Python generator for a star-schema dataset about a fictional enterprise
data and analytics vendor, "ACME Analytics." It exists for exercising analytics tools.

> ## WARNING: THIS IS A SYNTHETIC DATASET. NOTHING IN IT IS TRUE.
>
> **ACME Analytics is a fictional company, and all of its data is generated by a computer program.**
> Real company names appear for realism only. Their presence does not mean a company is, or ever was,
> a customer, prospect or partner of anyone. All customer status, churn, contracts, revenue, usage,
> sentiment and notes are invented, and none of it describes any real company. No real company has
> reviewed, endorsed or sponsored this project.
>
> **Use it only for testing and learning analytics tools.** Do not use it for research about these
> companies, sales or marketing, investment, credit or any other real-world decision. If you share the
> data, keep this notice with it. See [DATASET_README.md](DATASET_README.md).

The build spec is [ACME_DATASET_SPEC.md](ACME_DATASET_SPEC.md).

## Status

The generator is complete. `validate.py` passes 69 of 71 checks and exits non-zero because of the two
misses: FY22 NDR and FY23 NDR are each 0.5 points outside the 2-point tolerance.

## Setup

Requires [uv](https://docs.astral.sh/uv/).

    uv sync
    uv run python generate.py --config config.yaml
    uv run python validate.py

Generated CSVs are written to `output/lite/`. They are not stored in Git. The same seed and
config produce identical output. To skip the build, download the zip from
[Releases](https://github.com/naisan-original/ACME_Analytics_Dataset/releases).

`tools/tune.py` searches config values toward the KPI targets, and `tools/answer_key.py` writes the
facilitator key from the generated data.

## Loading the data

- `region` uses the value `NA` for North America, as the spec requires. Many tools, including pandas
  by default, read `NA` as null, so check this on import.
- Four fact tables share four dimensions, and fact tables should not be joined to each other row by row.
  See [How the tables join](DATASET_README.md#how-the-tables-join).
- `user_usage_month` is a sample. Use `sample_weight` to estimate population totals.
